# Кинотеатр им. Павлюка — ASP.NET Core MVC + SQLite

Учебный проект «Кинотеатр», вариант 4. Один проект C#, Razor, Bootstrap 5, Entity Framework Core и ASP.NET Core Identity. По текущему запросу база заменена на **SQLite**, название — **«Кинотеатр им. Павлюка»**. Светлый дизайн сохранён, каждому фильму назначена новая оригинальная обложка, рекламные материалы мессенджера убраны.

## Быстрый запуск в Visual Studio

1. Распакуйте архив и откройте `Cinema.sln` в Visual Studio 2022 17.8 или новее.
2. Нужна нагрузка «ASP.NET и разработка веб-приложений» и **.NET 8 SDK**.
3. Дождитесь восстановления NuGet, выберите профиль `Cinema`, нажмите **F5** или **Ctrl+F5**.
4. При первом запуске приложение само применит миграцию, создаст файл **App_Data/cinema.db** и заполнит начальные данные.

MySQL, отдельный сервер базы, Docker и Node.js для запуска сайта **не нужны**. SQLite включена в NuGet-пакеты приложения. Интернет нужен для первого восстановления пакетов; шрифты, Bootstrap и изображения находятся локально. Внешние карта и трейлеры требуют интернета.

Адреса: `https://localhost:7157` и `http://localhost:5157`. Панель управления — `/Admin`, команда — `/Team`.

Из терминала в папке Cinema.csproj:

```powershell
dotnet restore --configfile NuGet.Config
dotnet run
```

В Windows CMD можно просто выполнить `Start.cmd` из папки проекта или дважды щёлкнуть по нему. Скрипт использует локальный SDK этой рабочей папки, если он доступен, иначе установленный .NET SDK, и запускает сайт по адресу http://localhost:5157 без настройки HTTPS.

Если сертификат разработки ещё не настроен, для локальной демонстрации используйте HTTP-адрес.

## Файл базы данных

Настройка в appsettings.json:

```json
"ConnectionStrings": {
  "DefaultConnection": "Data Source=App_Data/cinema.db;Default Timeout=30;Foreign Keys=True"
}
```

Относительный путь считается от папки приложения. Приложение создаёт папку автоматически. База содержит пользователей, фильмы, сеансы, брони, билеты, оплаты, отзывы и настройки. После перезапуска данные сохраняются.

Если в секретах пользователя осталась строка подключения прежней MySQL-версии, удалите её или замените строкой SQLite выше: пользовательские секреты имеют приоритет над appsettings.json.

Для резервной копии **остановите приложение** и скопируйте файл базы; если рядом есть `-wal` / `-shm`, дождитесь корректного завершения всех подключений. Файлы базы исключены из исходного архива и .gitignore. Персональные данные и пароли пользователей в архив не включаются.

Используется новая миграция `InitialSqlite`. Миграции прежнего MySQL-провайдера в этой версии не используются; существующую MySQL-базу приложение не изменяет и автоматически из неё данные не импортирует.

## Что работает

- Афиша с фильтрами даты и жанра, карточки фильмов и расписание на месяц.
- Четыре зала: Синий, Красный, Зелёный, Оранжевый, отдельные схемы кресел.
- Несколько мест в одном заказе, серверный расчёт суммы, бронь на 10 минут.
- Учебная оплата без карты и реальных денег; отдельные электронные билеты, печать / сохранение в PDF.
- Identity: регистрация, вход/выход, профиль, пароль, личные заказы и история.
- Администратор: фильмы, постеры, сеансы, залы, роли, блокировка пользователей, модерация, услуги, FAQ, контакты, новости, баннеры, команда.
- Менеджер: заказы, учебная оплата, отмена и возврат до начала сеанса, просмотр отзывов. Управление пользователями и модерация ему запрещены на сервере.
- Форма контактов и отзывы сохраняют данные в SQLite; отзыв виден публично после одобрения.

Начальные данные: **28 фильмов, 4 зала, 496 сеансов на 31 день, 7 баннеров, 3 новости**, услуги, FAQ, команда и 3 учебных отзыва. Отдельного входа автора начальных отзывов нет: его учётная запись создана без пароля.

## Проверка покупки

1. Создайте обычный аккаунт через «Войти → Создать аккаунт».
2. Выберите фильм, будущую дату и сеанс.
3. Отметьте зелёные кресла. Они станут жёлтыми; итоговая стоимость изменится.
4. Подтвердите бронь, затем «Учебную оплату».
5. В личном кабинете откройте билеты: фильм, дата, время, зал, ряд, место и номер заказа.
6. Попробуйте открыть тот же заказ из другого аккаунта — доступ будет запрещён.
7. Создайте неоплаченную бронь и подождите 10 минут: кресла освободятся, оплатить старую бронь нельзя.
8. В двух браузерах одновременно бронируйте одно место: сервер разрешит только одну бронь.

Неоплаченную бронь можно отменить самостоятельно. Возврат оплаченного заказа выполняет менеджер до начала сеанса. Реальных списаний и возвратов денег нет.

## Почему нет двойной продажи

Каждое изменение брони начинается с транзакции SQLite. Microsoft.Data.Sqlite использует недеферрированную транзакцию по умолчанию: она получает право записи до проверки мест. В SQLite одновременно пишет один участник; второй запрос ждёт до завершения первого. Затем он видит уже занятое кресло.

Дополнительная защита — уникальный индекс `(SessionId, SeatId, Active)`. Active=1 удерживает место; NULL сохраняет историю отменённых/истёкших заказов, не мешая новой продаже. Оплата, очистка, отмена, возврат и изменения расписания используют транзакции. Блокировка SQLite распространяется на запись в базу, а не на отдельный зал: это подходит для локального учебного проекта.

Цены и суммы остаются decimal в C#. Сумма продаж вычисляется точно в .NET, поскольку SQLite-провайдер EF Core 8 не поддерживает SQL SUM для decimal. Подмена цены из браузера не принимается.

## Ограничения редактирования

Сеанс с заказами нельзя незаметно перенести или изменить ему цену. Фильм с созданными сеансами не позволяет менять длительность. Фильмы/сеансы с зависимостями не удаляются. При создании расписания учитываются длительность фильма и 20 минут на уборку; пересечения запрещены.

Ряды и места зала можно добавлять при существующих сеансах и заказах: ID старых кресел сохраняются. Удалить кресло с историей заказов нельзя. Отдельное кресло можно отключить, если на него нет действующих броней/билетов. Эти ограничения сохраняют смысл уже выданных билетов.

Зарегистрируйте ещё одного пользователя и назначьте ему роль менеджера через /Admin/Users. После изменения роли его прежняя авторизация аннулируется. При каждом запросе проверяется security stamp. Администратор не может заблокировать себя или понизить собственную роль.

Белый фон, розовые акценты, Montserrat и структура афиши основаны на сайте-образце. Новый логотип и первый баннер содержат «Кинотеатр им. Старые постеры обновятся автоматически и в ранее созданной базе SQLite при следующем запуске. Пользователи, заказы и цены сохраняются. Фотографии и базовые элементы оформления перечислены в docs/ASSET-SOURCES.md. Страна производства фильма «Россия» остаётся корректной метаинформацией и не является старым названием кинотеатра.

В «Главная и контакты» редактируются заголовки/изображения/ссылки семи баннеров, новости, контакты и тексты. Ссылки баннеров должны быть внутренними, изображения — из /images/ или /uploads/. Карта и адрес учебные. Имена четырёх участников команды изменяются в /Admin без правок кода.

## Структура

| Папка | Содержимое |
|---|---|
| Controllers | Публичные страницы, аккаунт, билеты, отзывы |
| Models | Сущности и статусы |
| ViewModels | Формы и данные страниц |
| Data | DbContext, начальные данные, фабрика для EF CLI |
| Services | Бронирование, учебная оплата, очистка, часы |
| Areas/Admin | Контроллеры и представления админки |
| Views | Razor HTML |
| wwwroot | CSS, JavaScript, Bootstrap, шрифты, изображения |
| Migrations | InitialSqlite и снимок модели |
| App_Data | Локальный файл базы после первого запуска |
| tests | Необязательный интеграционный прогон |

Контроллер → DbContext/BookingService → SQLite → Razor. Repository, CQRS, MediatR, React и отдельного frontend-проекта нет.

## Проверки и дальнейшие изменения

Сборка: `dotnet build -c Release`. Протокол — docs/VERIFICATION.md. Для повторения HTTP/SQLite-проверок дополнительно нужен Node.js 24+, инструкция — tests/README.md. Для работы сайта Node.js не требуется.

После изменения моделей:

```powershell
dotnet tool restore
dotnet ef migrations add НазваниеИзменения
dotnet run
```

Приложение применяет миграции при запуске. Запускайте один экземпляр во время обновления схемы. При изменении модели существующие данные не удаляются через EnsureDeleted/EnsureCreated.

Время сеансов — местное время кинотеатра, по умолчанию UTC+4 (Cinema:UtcOffsetHours). Сроки брони хранятся в UTC. Расписание создаётся относительно первого запуска; позднее добавляйте сеансы через админку.

Учебная оплата выделена в IPaymentService. Будущий реальный адаптер должен подтверждать оплату после проверки статуса у провайдера на сервере; данные карты хранить нельзя. Восстановление пароля по почте, реальный эквайринг и фискализация в учебный режим не входят.

При ограниченных правах на профиль Windows можно задать DataProtection:KeysPath в доступную папку вне wwwroot и репозитория. На Windows ключи защищаются DPAPI. Не включайте ключи, пользовательские секреты и реальные базы в архив исходников.
